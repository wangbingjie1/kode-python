# 用户已确认的业务规则（构建本体时必须遵守）

## 规则 1: task vs platform_ai_conversation
**类型**: 命名一致性
**问题**: task 表和 platform_ai_conversation 表似乎表示相同的业务概念（AI对话会话），但使用了不同的命名和字段设计。task.robot_id 和 platform_ai_conversation.agent_id 是否指向同一实体？
**用户确认**: task 是多媒体模型的队列表，platform_ai_conversation  是会话模型的日志表，robot_id 和agent_id  是模型ID

## 规则 2: message.task_id, platform_ai_conversation_msg.conversation_id
**类型**: 数据完整性
**问题**: message 表的 task_id 和 platform_ai_conversation_msg 表的 conversation_id 缺少外键约束，无法确定引用关系的有效性
**用户确认**: message表是divino产品的，platform_ai_conversation_msg是glbgpt产品的，他俩没有关系

## 规则 3: candy_chat_girl_friend, crush_chat_boy_friend
**类型**: 业务语义
**问题**: 这两个表结构完全相同，仅表名不同。为什么需要分成两个表？是否应该合并为一个表并添加 gender/type 字段？
**用户确认**: 两个产品的独立表

## 规则 4: conversation_id 字段
**类型**: 数据完整性
**问题**: 多个表中的 conversation_id 字段（candy_chat_girl_friend, crush_chat_boy_friend, note_chat_conversation）缺少外键约束，无法确定是否都引用 platform_ai_conversation.id
**用户确认**: 他们之间没有关系，candy_chat_girl_friend, crush_chat_boy_friend, note_chat_conversation是老产品的，已经废弃了
