1. SSE 连接无自动重连机制【高风险】
   文件: web-frontend/src/services/sse.ts
   影响: 用户在网络波动时永久失连，必须刷新页面
   影响范围: 100% 用户
   修复时间: 2-3小时
   
   问题说明:
   - EventSource 无重连配置
   - 连接断开后用户无法自动恢复
   - 弱网环境下完全无法使用
   
   修复方案:
   ✓ 添加指数退避重连（1s, 2s, 4s, 8s, 16s）
   ✓ 最大重试5次，之后主动断开
   ✓ 保存待发消息，重连后继续发送
   ✓ 添加30秒连接超时检测
   
   测试方法:
   1. 使用 Chrome DevTools Network 限流（Slow 3G）
   2. 发送消息
   3. 在传输中强制断网
   4. 验证是否在 5-10 秒内自动重连

---

2. ChatStore 事件监听器内存泄漏【高风险】
   文件: web-frontend/src/stores/chat.ts（第72-97行）
   影响: 长期使用导致应用响应速度变慢，浏览器卡顿
   症状: 切换 10+ 对话后，处理速度明显下降
   修复时间: 1小时
   
   问题说明:
   - 每次 connectToConversation 注册新回调，旧回调不清除
   - SSE 是单例，回调持续累积
   - 同一事件会触发多个版本的回调处理
   
   根本原因代码:
     sseService.clearCallbacks()  // 清空数组
     sseService.onMessage((chunk) => { ... })  // 但新回调继续累积
     sseService.onError((error) => { ... })
     sseService.onClose(() => { ... })
   
   修复方案:
   ✓ 改用 sseService.reset() 完全重置状态（而不仅仅 clearCallbacks）
   ✓ 或改为事件监听器模式（发布-订阅）
   
   验证:
   1. Chrome DevTools → Memory
   2. 打开 ChatView，切换 10+ 次对话
   3. 手动触发垃圾回收
   4. 检查内存占用（应该相对稳定，不超过 50MB）

---

3. ChatView 定时器未清理【高风险】
   文件: web-frontend/src/views/ChatView.vue（第229-250, 470-480行）
   影响: 组件卸载后定时器继续运行，导致内存泄漏
   修复时间: 15分钟
   
   问题说明:
   let scrollThrottle = null
   
   watch(...) {
     scrollThrottle = setTimeout(...)  // 创建定时器
   }
   
   onUnmounted(() => {
     // 但这里没有清理 scrollThrottle !!!
   })
   
   修复:
   ✓ 在 onUnmounted 中添加:
     if (scrollThrottle) {
       clearTimeout(scrollThrottle)
       scrollThrottle = null
     }

4. SSE 通过 URL 参数传递 Token【安全风险】
   文件: web-frontend/src/services/sse.ts（第58-64行）
   安全风险: Token 泄露导致账户被劫持
   
   问题:
   https://app.example.com/api/sse/chat/123/stream?task=xxx&token=eyJhbGc...
   
   风险:
   ✗ Token 被保存在浏览器历史记录
   ✗ 用户分享屏幕截图时 token 可能暴露
   ✗ 企业代理日志中会记录 token
   ✗ 浏览器扩展可能访问 URL
   
   修复方案（需后端配合）:
   ✓ 后端支持 Authorization header（推荐）
   ✓ 改为 POST 请求，token 在请求体中
   ✓ 或使用一次性 session token

---

5. 登录表单验证不足【安全风险】
   文件: web-frontend/src/views/LoginView.vue（第15-34, 174-182行）
   问题: 仅依赖 HTML5 required 属性，容易被绕过
   修复时间: 1.5小时
   
   当前问题:
   <input required v-model="password" />
   
   可以通过以下方式绕过:
   1. 浏览器开发者工具移除 required 属性
   2. 直接调用 API: curl -X POST /auth/login -d '{"username":"a","password":"b"}'
   
   修复方案:
   ✓ 添加客户端 JS 验证
   ✓ 检查密码强度（大小写+数字+特殊字符）
   ✓ 验证邮箱格式
   ✓ 检查用户名长度（3-50字符）
   
   示例验证函数:
   function isStrongPassword(password: string): boolean {
     const hasUpper = /[A-Z]/.test(password)
     const hasLower = /[a-z]/.test(password)
     const hasDigit = /[0-9]/.test(password)
     const hasSpecial = /[!@#$%^&*()_+\-=\[\]{};':"\\|,.<>\/?]/.test(password)
     return hasUpper && hasLower && (hasDigit || hasSpecial)
   }

6. API 401 错误处理不优雅【中等风险】
   文件: web-frontend/src/services/api.ts（第39-78行）
   问题: 
   - 动态导入 useAuthStore 两次（循环依赖风险）
   - 没有防止无限重试的机制
   修复时间: 1小时
   
   当前问题代码:
   try {
     const { useAuthStore } = await import('@/stores/auth')  // 第一次
     const authStore = useAuthStore()
   } catch (refreshError) {
     const { useAuthStore } = await import('@/stores/auth')  // 第二次！
   }
   
   修复方案:
   ✓ 缓存 authStore 实例
   ✓ 避免重复导入
   ✓ 添加 _retry 标志防止重试循环
